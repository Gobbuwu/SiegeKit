# 0027. Running ffuf

- Status: Accepted
- Date: 2026-11-20
- Amends: [0004](0004-plugin-manifest.md) (field `run.wordlist`, placeholder `{wordlist}`, parser `ffuf-json`), [0024](0024-pinned-file-downloads.md) (a wordlist ships inside SiegeKit instead of being downloaded)

## Context

ADR 0025 item 2 gives ffuf SecLists `Discovery/Web-Content/common.txt` on local targets and a list of about 200 paths that SiegeKit writes itself on deployed targets. ADR 0024 item 1 and the owner's answer to question 2 put ffuf's static binary in the pinned Alpine image. Facts checked on 2026-11-20:

- **ffuf 2.3.0.** The release has `ffuf_2.3.0_linux_amd64.tar.gz` (4,367,536 bytes) and `ffuf_2.3.0_linux_arm64.tar.gz` (3,950,470 bytes). Their SHA-256 values match the publisher's `ffuf_2.3.0_checksums.txt`. Each archive holds `ffuf`, a statically linked binary that reports `ffuf version: 2.3.0` in the pinned Alpine image, plus its README, changelog and MIT license. The files in the archives are dated 2026-09-09; ADR 0025 checked that the release is more than 7 days old (ADR 0008).
- **SecLists.** It publishes no release files, only GitHub's generated archive of the whole repository, for one 38,536-byte file. Tag `2026.2` (commit `145f1f45ba7bc5fd6b3966d3a79bf95654deb20e`, 2026-10-26) has `common.txt` with 4,751 paths, SHA-256 `47fb86ca…956a`, under the MIT license (copyright 2018 Daniel Miessler), whose text must go with every copy.
- **ffuf's output.** Its JSON report (`-of json`) lists each match with status, size, content type, redirect and URL. Auto-calibration (`-ac`) learns the app's answer to a made-up path: against a server that answers every path with the same page, only the path with a different answer was reported (measured).

## Decision

1. **The SecLists list ships inside SiegeKit.** This is the owner's choice of 2026-11-20, over downloading SecLists' generated archive or allowing single raw files from GitHub. `internal/wordlists` holds the pinned file byte for byte (a test checks its SHA-256) and SiegeKit's own list `deployed.txt` (210 paths: environment files, version-control folders, backups and dumps, configuration files, logs, admin and API-documentation pages). SecLists' license text is kept beside the list (`SECLISTS-LICENSE`) and named in THIRD_PARTY.md. Both lists are part of the binary, so nothing is downloaded and no consent question is asked for them. Updating SecLists means a reviewed pull request.
2. **Manifest.** `run.wordlist` names a list for each mode (`local`, `deployed`). It is allowed only for plugins whose only target is `url`, and `{wordlist}` in the arguments needs it. SiegeKit writes the chosen list to the run's directory and mounts it read-only at `/siegekit/files/wordlist/paths.txt`. No artifact may use that mount.
3. **`ffuf`** runs on every target, from its pinned archive in the pinned Alpine image:
   - It asks for `{target-base}/FUZZ` with GET requests (ADR 0026: no double slash). On deployed targets the proxy allows only GET and HEAD anyway (ADR 0023).
   - Its proxy is the relay (`-x`), at `{ratelimit}` requests per second, with 8 threads.
   - Auto-calibration is on.
   - It matches ffuf's default statuses: 200 to 299, 301, 302, 307, 401, 403, 405 and 500.
4. **Results** are read by a new parser, `ffuf-json`. Each matched URL becomes one informational finding, `path-found`, whose message gives the status, size, content type and redirect. A guessed path is worth a look, not a flaw by itself. Request headers and ffuf's settings are not copied.
5. **Resources:** 1 CPU, 512 MiB, 10 minutes. A local run of 4,751 paths took 53 seconds. At 10 per second, the deployed list takes about 21 seconds.

## Consequences

- A local scan sends about 4,760 more requests, and a deployed scan about 215.
- The report's "Not tested" list states that deployed targets get the short list, so files with other names are missed there (ADR 0025).
- Auto-calibration can hide a real file whose answer looks like the app's answer to any path.
- Paths that the app redirects are reported, as ffuf matches 301 and 302. Against the test app, SecLists' entry `render/https://www.google.com` is reported only because Go's server redirects the double slash. It is counted in the M2 result-quality triage.
- ffuf reports files by name only. Nuclei's templates check what an exposed file contains (ADR 0026).

## Alternatives considered

- Downloading SecLists' generated archive of the whole repository: a large download for one 38 KB file, with bytes GitHub may change. Rejected by the owner.
- Allowing `raw.githubusercontent.com` for single files pinned by commit and SHA-256: this widens the rule that pinned files come only from publisher releases (ADR 0024). Rejected by the owner.
- Two plugins, one per mode, like ZAP: they would differ only in the list, and the mode already decides which list is used.
