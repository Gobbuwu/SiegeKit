# 0053. Routes read from the app's server code for the route sweep

- Status: Accepted (owner 2026-11-22 06:29 UTC, decision card "Spec + server code (E2), with B": this ADR is pull request 3 of 3, routes from server code; owner 2026-11-22 16:43 UTC "okay do it". Build-time items 1 to 8 are Claude's, measured below and brought to the owner with the pull request)
- Date: 2026-11-22
- Amends: [0037](0037-backend-live-check.md) (what `--source` is read for), [0052](0052-route-sweep.md) (which routes the sweep sends; how an optional ID filter is filled)

## Context

The route sweep (ADR 0052) sends outsider C every GET route of the app's API spec, filled with IDs from A's recording. It found Rocket.Chat's `chat.getDeletedMessages` leak, which no first-party client calls. Without a spec it sends nothing: of the 7 test apps used so far only Gitea, DVGA and Wiki.js serve one, Rocket.Chat and Mattermost publish theirs elsewhere, and Gitea's covers only its REST API, not its web pages (record `outsider-shared-space-2026-11-22.md`, Parts 3 and 4, in the project's shared files). An attacker who has the code reads the routes from it, and so does the person who owns a local app. Measured before the decision: Rocket.Chat's server bundle lists all 122 room routes and finds the leak; Mattermost's Go source lists 62 of its 63 spec routes plus 11 the spec lacks; browser JavaScript and wordlists did not reach the leak.

The code says which paths exist. It does not say which query parameters a route needs: `chat.getDeletedMessages` answers "The required "roomId" query param is missing" to a bare call, so a path alone does not test it.

## Decision

1. **Input.** `--source DIR`, the app's repository (ADR 0037), is also read for routes, on local targets only, for `access-control`'s route sweep. No new flag. A directory holding only a server bundle works too (Rocket.Chat's images ship `bundle/programs/server/app/app.js`, 20 to 24 MB). Deployed targets: unchanged, the code is not read for routes.
2. **What is read.** Files ending in `.go`, `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`, never run. Skipped: test files (`_test.go`, `.test.`, `.spec.`, `.d.ts`), and folders of dependencies, version control, build caches, tests (`node_modules`, `vendor`, `.git`, `testdata`, `test`, `tests`, `__tests__`, `e2e`...) and browser code (`client`: its HTTP calls, such as `sdk.rest.get('/v1/users.presence', params)`, are shaped like Express routes; in Rocket.Chat 8.9.1 they gave 16 paths no server registers). Symbolic links are not followed. At most 64 MiB per file, 50,000 files and 512 MiB in all; files past a limit are counted.
3. **Extractors, one per way of registering routes.**
   - **Go**, read with the standard `go/parser` (no build, no type checking): router values are followed through the code from a known constructor (`mux.NewRouter`, `chi.NewRouter`, `web.NewRouter`, `gin.Default`, `echo.New`, `http.NewServeMux`...) or a parameter of a router type, through sub-routers with a prefix (`PathPrefix(p).Subrouter()`, `Group(p)`, `Route(p, fn)`, Gitea's `Group(p, fn)`, which changes the prefix of the same router while `fn` runs), routers kept in struct fields (`api.BaseRoutes.Channel`), string constants in other packages of the tree (`model.APIURLSuffix`, through the tree's `go.mod` files), calls into the tree's functions with the routers they are given, and `Mount(p, pkg.Routes())`. Registrations: `Handle`, `HandleFunc` and `PathPrefix(p).Handler(h)` with `.Methods(...)`, `Get`/`GET` and the other method names, `Methods("GET,POST", p, ...)`, `Method`, `Match`, `Combo(p).Get(...)`, `Any`, and `"GET /path/{id}"` patterns. A function walked again with the same routers is not walked twice, and the walk stops after 5,000,000 statements.
   - **Rocket.Chat's REST API**, read with a small JavaScript tokenizer that tells strings, template literals, comments and regular expressions apart: `API.v1.addRoute('name' or ['a', 'b'], options, { get() {...} })` and the chained `API.v1.get('name', options, handler).post(...)`, under `/api/v1/` (`API.default` under `/api/`, `API.experimental` under `/api/experimental/`).
   - **Express**: `x.get('/path', ...)`, `x.all('/path', ...)`, `x.route('/path').get(...)` with a string path starting with `/`. A router mounted with `app.use('/prefix', router)` is not followed.
4. **Paths.** Path parameters become `{name}` (`{id:[0-9]+}`, `:id`). A parameter whose pattern only lists words (`{syncable_type:teams|channels}`) becomes one path per word, at most 16. A path with a wildcard (`*`, `{path...}`), an optional or regex Express parameter, or a part the code builds at run time, is not sent and is counted. Only GET routes and routes registered for any method are kept: the sweep reads.
5. **Query parameters, from the handler's code.** The names a route's handler reads (`this.queryParams` and `req.query` in JavaScript, by member or destructuring; `r.URL.Query().Get`, `FormValue`, Gitea's `ctx.Form*`, gin's and echo's query readers in Go) are kept. The code does not say which are required, so: a name that asks for an object ID (ADR 0052 item 4) is filled with A's IDs when the recording showed one that fits and left out otherwise, never dropping the route; a lower date bound (`since`, `after`, `from`) is always sent with `1970-01-01T00:00:00.000Z` (refused when missing, and it narrows nothing); other names (paging, search text, upper date bounds) are left out. Path parameters are filled as in ADR 0052 item 4.
6. **With a spec.** A code route whose path the spec also has (parameter names aside) is swept from the spec, which says what is required; the rest of the code routes are swept after the spec's. Both share the sweep's limit of 500 (ADR 0052 item 7), and everything else of ADR 0052 applies: action names skipped, address parameters never filled, A's headers carried, the read rules and tiers of ADR 0035 and 0051, 429 counted.
7. **Reporting.** The plan says the code's routes are swept and how many were found. The report's input names the folder, the files read, the routes found per extractor, how many the spec already had, the requests swept from them, and each kind of route not followed; the result says how many swept requests came from the code.
8. **Nothing else is sent.** The code is read locally; only the swept GET requests go to the local target.

## Consequences

- Without a spec, the outsider test now reaches the routes of local apps whose code SiegeKit can read: Rocket.Chat's leak is found from its source or from the bundle in its own image, and Juice Shop's user list from its compiled server. Gitea's web pages are swept for the first time (its API refuses the browser's cookie).
- **More requests and the same false alarms.** Code-only runs swept 359 to 397 requests on Rocket.Chat and Mattermost, 216 to 229 on Gitea. The by-design lists every logged-in account gets are the ones the spec sweep already reports (ADR 0052, backed by each app's code), so the M2 milestone check question stays the same: whether routes with no object ID should be lowered.
- **The target may contact other sites, or write, by itself.** A GET route whose handler opens a connection elsewhere or creates data is sent like any other (measured on 8 apps: Juice Shop's `nftMintListen`, 4 lookups of alchemy.com; HedgeDoc's `GET /new`, one note per run). The address rule of ADR 0052 item 5 only covers a parameter the sweep fills. A recording or a spec that holds such a route replays it too (ADR 0035, 0052); the code reaches routes neither holds. The sweep runs only on local targets. How to handle these is brought to the owner as a decision (2026-11-22): accept and document, skip routes the code shows acting, code routes only on request, or ask for an offline target.
- **Not covered:** frameworks other than the ones in item 3 (Django, Flask, Rails, Spring, Laravel, PHP, Fastify's and Hono's own forms, Next.js file routes); routes built at run time, router values mounted through a variable or dependency injection (Navidrome's `/api` and `/rest`: their routes are sent without the prefix and answer 404), wildcards (counted); Rocket.Chat's Apps-engine routes; query parameters read through helpers (`getPaginationItems`) or validators rather than in the handler; slug-named parameters such as Gitea's `{username}/{reponame}` (460 Gitea routes not sent); IDs the recording did not show (no guessing, a separate item); writes.
- `--source` is read once more, locally; a large tree costs time and memory (Gitea's 2,059 Go files: 0.8 s and 137 MB; Rocket.Chat's 24 MB bundle: 3.2 s and 278 MB, measured with the extractor alone).

## Alternatives considered

- **A new flag (`--routes-from`)** instead of `--source`: the same folder would be given twice. `--source` is already "the app's repository" (ADR 0037).
- **Query parameters**: path parameters only (misses Rocket.Chat's leak), or every name the handler reads as required (44 more Rocket.Chat routes dropped for want of an ID, 9 fewer answered); measured in the table above. Asking the app (send the route bare, read "The required "roomId" query param is missing", add it, as an attacker probing does): not built; it costs a request per missing parameter and depends on each app's error text.
- **Code in `client/` folders kept**: Rocket.Chat 8.9.1's browser code gave 16 paths no server registers (`sdk.rest.get('/v1/users.presence', params)`), all of them sent; skipping the folder removed all 16 and no server route.
- **Files up to 8 MiB**: Rocket.Chat's server bundles (20 and 24 MB) would not be read; with 64 MiB they are, each read and dropped in turn.
- **Any method call shaped like `Get(...)` marks a routing function**: on Gitea every function calling `cache.Get(key)` was walked, and the walk did not end (the test binary crashed); only path-shaped literal arguments mark one now, and a function walked with the same routers is not walked again.
- **Skipping GET routes whose handler contacts other sites**: not built; telling that from the code needs every HTTP, WebSocket and SDK client known, and a miss would still send. Stated under Consequences instead.
