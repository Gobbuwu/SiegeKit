# Re-check of 2026-11-19

The owner asked for a full re-check of everything built so far before work continued. This is the record of what was checked, what was found and what was done.

Scope: README, all docs, ADRs 0002–0018, THIRD_PARTY, CONTRIBUTING and CI workflows, checked against the code on `main` (9a2bb0a). I used real runs on Linux with Docker 29.10.0: a planted repo, AI-key detection, root runs, URL target rules and a Go 1.26.0 build.

## Verified working as documented
- Planted repo: every check that ran found its planted issue.
  - Committed `.env` found in git history, and `.env` not in `.gitignore` flagged.
  - AWS key found in both files and history.
  - Public Firestore rule and Supabase table without RLS flagged.
  - Dockerfile and Terraform issues found by checkov.
- OpenAI (`sk-proj-…`) and Anthropic (`sk-ant-api03-…`) keys are detected by gitleaks, as coverage.md claims.
- Without a terminal and without `--yes`, nothing is installed. Missing tools are listed with their sizes and their checks are skipped, as ADR 0016 says.
- Reports:
  - Written with mode 0600.
  - The HTML has a strict CSP and no external resources.
  - No "secure", "passed" or "safe" wording. Secrets are masked.
- Every engine sandbox flag in ADR 0006 is present: no network, read-only target, cap-drop ALL, no-new-privileges, read-only root, pids, memory and CPU limits, `--pull never`.
- URL rules (ADR 0005/0017):
  - Loopback is allowed.
  - A private address without a terminal is refused.
  - 169.254.169.254 and `0x7f000001` are refused.
  - `--deployed` refuses `--authorized-host`.
- The code builds with Go 1.26.0, which go.mod and the README name as the minimum.

## Bugs fixed
- **#20:**
  - The report's "Not tested" list claimed a two-account access test that does not exist. It now says the running app and non-Python/Go code are not analyzed.
  - Tool messages showed the container path (`/target/cfg.py`).
  - `--deployed --authorized-host` did a DNS lookup before refusing.
  - The dotenv `.gitignore` matcher had no fuzz target (ADR 0015).
- **#21:**
  - As root, files only root could read were silently not scanned. A 0600 file with an API key gave "no issues", exit 0.
  - Now those files are listed and the check is marked incomplete (exit 4), as the owner decided.

## Doc drift fixed (#20)
- coverage.md:
  - It claimed Trivy covers secrets in images, base-image packages and IaC in M1. Trivy only scans dependency files, and SiegeKit has no image targets.
  - OSV-Scanner, Syft and Grype were listed as M1.
- coverage.md and standards-mapping.md still named Semgrep, which was replaced by Opengrep.
- THIRD_PARTY.md:
  - The pinned-image table was broken, so the bandit and gosec rows did not render.
  - The gitleaks-history row was missing.
  - Nmap was said to be used if installed, which contradicts ADR 0016.
- Threat model, README and CONTRIBUTING had stale M1 notes.

## Decided after the re-check (owner, 2026-11-19)
- When run as root: list files the tool user cannot read, and mark the checks that need them incomplete. Done in #21.
- Suppressions in the scanned repository: obeyed, but counted in every report. Done in #23 (ADR 0020).
- The relay image `alpine/socat` comes from a personal Docker Hub organization, not the Alpine project. Replaced by SiegeKit's own relay binary in the official Alpine image, in #24 (ADR 0021).
- The 9 items that earlier ADRs decided but no plan scheduled are placed in [the M2 plan](m2-plan.md#follow-ups-from-the-re-check-of-2026-11-19).
