# What SiegeKit checks

Each row is a common security concern, the plugins planned to check it, and the milestone that delivers it. Rows were checked against the code on 2026-11-19; M1 rows are what the current version runs. "Manual" rows are not automated; see the [pre-deploy checklist](pre-deploy-checklist.md). Tools are listed in [THIRD_PARTY.md](../THIRD_PARTY.md). For coverage against the OWASP and CWE lists, see [standards mapping](standards-mapping.md).

| Concern | Checked by | Milestone |
| --- | --- | --- |
| API keys, tokens, private keys in source code and **git history** | Gitleaks (files, M1); gitleaks-history (every commit on every branch, including secrets deleted later; added in M2 on 2026-11-19, because M1 scanned only the files); TruffleHog (optional) | M1, M2 |
| Environment files (`.env`, `.env.local` and similar) committed to git, or not excluded by `.gitignore` | gitleaks-history (committed in any commit); built-in `dotenv-gitignore` (not excluded, so `git add .` would commit it). Templates such as `.env.example` are allowed. Added at the owner's request on 2026-11-19. | M2 |
| Weak or default passwords written into config files, URLs and code (`admin123`, `postgres`/`postgres`, values on the 10,000 most common passwords) | Built-in `weak-passwords`: SecLists 10,000 most common plus vendor defaults, shorter than 12 characters, or equal to the user or key name; tests, translation files, documentation, templates and comments are skipped and counted; long weak passphrases are missed (delivered in M2.6d, [ADR 0034](adr/0034-weak-passwords.md)) | M2 |
| Secrets inside container images | Trivy (needs container-image targets, which SiegeKit does not support yet) | M3 |
| Secrets exposed by a running site (JS bundles, public `.env`, `.git/`, backups) | Nuclei exposure templates on every URL target (delivered in M2.5b, [ADR 0026](adr/0026-nuclei.md)); `served-secrets`: Gitleaks on the start page and the same-origin scripts, styles, JSON files and source maps it links, at most 200 requests, on every target; scripts loaded later by other scripts, other pages and other origins are not fetched (delivered in M2.6c, [ADR 0032](adr/0032-served-secrets.md)); ffuf | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| Outdated libraries with known vulnerabilities | Trivy, from lock and manifest files (M1); OSV-Scanner, Grype (M2) | M1, M2 |
| Outdated container base images and OS packages | Trivy, Grype (needs container-image targets) | M3 |
| Software inventory (what versions you ship) | Syft (SBOM) | M2 |
| Old or forgotten endpoints, backup and leftover files, directory listings | ffuf on every URL target: SecLists `common.txt` (4,751 paths) on local targets, SiegeKit's own 210 paths on deployed ones (delivered in M2.5c, [ADR 0027](adr/0027-ffuf.md)); Nuclei; Nikto (optional) | M2 |
| Exposed admin pages and dashboards | Nuclei panel templates (delivered in M2.5b), ffuf (delivered in M2.5c), ZAP spider | M2 |
| Default vendor logins left enabled | `nuclei-default-login`: Nuclei's 337 HTTP default-login templates (pinned v10.5.2), each documented factory login sent once (PeopleSoft's on each of 20 paths), on local targets after confirmation; non-HTTP services (SSH, databases) and the WordPress password-list template are not run (delivered in M2.6b, [ADR 0031](adr/0031-default-logins.md)) | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| No limit on failed login attempts | `login-throttle`: up to 50 logins (20 by default) for your own test account with a random wrong password, one per second, on local targets; deployed targets from M2.10 (delivered in M2.6a, [ADR 0030](adr/0030-login-throttling.md)) | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| Session cookie flags, security headers, TLS settings | ZAP crawl and passive checks on every URL target (delivered in M2.4, [ADR 0023](adr/0023-active-web-scans.md)); Nuclei header and cookie templates on every URL target (delivered in M2.5b). TLS settings: not yet, Nuclei's SSL templates cannot pass the egress proxy | M2 |
| Injection (SQL, command, template), XSS, SSRF patterns | Bandit (Python) and gosec (Go) code, M1; Opengrep for other languages, M2; ZAP attack scan on the running app, local targets only (delivered in M2.4; deployed targets wait for M2.10); Nuclei, sqlmap, M2 | M1, M2 |
| Known CVEs in deployed software | Nuclei CVE templates on every URL target; intrusive ones on local targets only (delivered in M2.5b) | M2 |
| API endpoints that crash or leak errors on bad input | Schemathesis on local URL targets with an OpenAPI or Swagger 2.0 spec, from `--openapi` or found at one of 10 common paths (delivered in M2.5d, [ADR 0028](adr/0028-schemathesis.md)). APIs without a spec are not tested by it | M2 |
| Misconfigured Dockerfiles, Kubernetes, Terraform | Checkov (M1); Hadolint (optional, not scheduled). Trivy runs only its dependency scanner. | M1 |
| Crashes and memory bugs on malformed input | Go fuzzing, Atheris, cargo-fuzz, AFL++ (optional) | M3 |
| Weak password hashes in data you supply | hashcat (GPU), John the Ripper (CPU), offline only | M3 |
| One user reading or changing another user's data (IDOR/BOLA), admin functions open to normal users | `access-control`: the GET and HEAD requests of a browser recording made as test account A (`--har`, at most 100), plus OpenAPI GET routes without path parameters, replayed as account B (`SIEGEKIT_SESSION_B`); reported when B gets A's exact answer, with data, while no login is refused; high with an ID in the URL or A's login name in the answer, otherwise medium (check by hand). On every URL target. Heuristic and partial: pages the recording did not reach, other IDs, changes (POST, PUT, PATCH, DELETE) and answers that differ on every request are not tested (delivered in M2.7a, [ADR 0035](adr/0035-access-control-replay.md)) | M2 ([ADR 0011](adr/0011-app-logic-and-ai-checks.md)) |
| API routes with no login required | `access-control`: each replayed request is also sent with no login; reported (medium: public pages name their authors by design) when it gets A's exact answer containing A's login name (`--har-user`), and high (`no-login-secret`) when a JSON answer has a field named like a password, hash, secret, key or token with a value, such as Juice Shop's password hashes or Memos's OAuth client secret (CVE-2025-65797). Data readable with no login that neither names A nor has such a field, such as other users' names and addresses, is not reported (delivered in M2.7a, [ADR 0035](adr/0035-access-control-replay.md)) | M2 (ADR 0011) |
| Supabase tables without row-level security, open Firebase rules | Static rules (M1); `backend-live`: one read-only GET per Supabase table or Realtime Database path with the app's own public key, names from the app's scripts and `--source` migrations and rules; the backend must appear in the scripts and a person types its host (M2.7c). Not tested live: Firestore, Cloud Storage, tables named nowhere, writes | M1, M2 (ADR 0011, [0037](adr/0037-backend-live-check.md)) |
| Missing rate limits on expensive or AI endpoints | `rate-limit`: up to 50 requests (20 by default), one per second, to one URL you name with `--rate-limit-url` (GET, or POST with `--rate-limit-body`), on local targets; a limit counts as seen at a 429 or 503 answer or a `Retry-After`, `RateLimit-*` or `X-RateLimit-*` header; no limit is low. URLs behind a login, limits above the burst, per-IP limits and limits that only slow answers are not tested; deployed targets from M2.10 (delivered in M2.7b, [ADR 0036](adr/0036-rate-limit-check.md)) | M2 ([ADR 0011](adr/0011-app-logic-and-ai-checks.md)) |
| CORS misconfiguration, open redirects, CSRF, file-upload flaws, path traversal, SSRF | Bandit and gosec where they have rules (M1); Opengrep (M2); ZAP attack scan on local targets (path traversal tested in M2.4); Nuclei on the running app (M2.5b: non-intrusive templates everywhere, intrusive ones such as PUT uploads on local targets only) | M1, M2 |
| AI provider keys (OpenAI, Anthropic and others) in code or bundles | Gitleaks | M1, M2 |
| AI model output reaching eval, shell, SQL or HTML unescaped | Static rules | M3 (ADR 0011) |
| Prompt injection and system-prompt leakage in the app's AI features | garak or promptfoo, optional | M3 (ADR 0011) |
| Mass assignment, excessive AI agency, logging gaps | Manual | n/a |
| Business-logic flaws (skipping steps, price tampering) | Manual | n/a |
| Cloud account settings (buckets, IAM, firewalls) | Manual (not in scope for 1.0) | n/a |
| Password guessing against live logins | Not provided, by design | n/a |

Declined on 2026-11-19 by the owner: flagging runtimes and frameworks that are past end-of-life without a known vulnerability. It is not a security issue in itself, and no data source with a confirmed license was found. Known vulnerabilities in old versions are still found by Trivy.
