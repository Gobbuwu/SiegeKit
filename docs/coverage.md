# What SiegeKit checks

Each row is a common security concern, the plugins planned to check it, and the milestone that delivers it. Rows were checked against the code on 2026-11-19; M1 rows are what the current version runs. "Manual" rows are not automated; see the [pre-deploy checklist](pre-deploy-checklist.md). Tools are listed in [THIRD_PARTY.md](../THIRD_PARTY.md). For coverage against the OWASP and CWE lists, see [standards mapping](standards-mapping.md).

| Concern | Checked by | Milestone |
| --- | --- | --- |
| API keys, tokens, private keys in source code and **git history** | Gitleaks (files, M1); gitleaks-history (every commit on every branch, including secrets deleted later; added in M2 on 2026-11-19, because M1 scanned only the files); TruffleHog (optional) | M1, M2 |
| Environment files (`.env`, `.env.local` and similar) committed to git, or not excluded by `.gitignore` | gitleaks-history (committed in any commit); built-in `dotenv-gitignore` (not excluded, so `git add .` would commit it). Templates such as `.env.example` are allowed. Added at the owner's request on 2026-11-19. | M2 |
| Weak or default passwords written into config files, URLs and code (`admin123`, `postgres`/`postgres`, values on the 10,000 most common passwords) | Built-in `weak-passwords`: SecLists 10,000 most common plus vendor defaults, shorter than 12 characters, or equal to the user or key name; tests, translation files, documentation, templates and comments are skipped and counted; long weak passphrases are missed (delivered in M2.6d, [ADR 0034](adr/0034-weak-passwords.md)); SQL `crypt('...')` seed passwords since [ADR 0064](adr/0064-static-supabase-rules.md) | M2 |
| Secrets inside container images | Trivy (needs container-image targets, which SiegeKit does not support yet) | M3 |
| Secrets exposed by a running site (JS bundles, public `.env`, `.git/`, backups) | Nuclei exposure templates on every URL target (delivered in M2.5b, [ADR 0026](adr/0026-nuclei.md)); `served-secrets`: Gitleaks on the start page and the same-origin scripts, styles, JSON files and source maps it links (and `<file>.map` when a file names none, [ADR 0046](adr/0046-public-api-maps.md)), at most 200 requests, on every target; scripts loaded later by other scripts, other pages and other origins are not fetched (delivered in M2.6c, [ADR 0032](adr/0032-served-secrets.md)); ffuf | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| Outdated libraries with known vulnerabilities | Trivy, from lock and manifest files (M1); OSV-Scanner, Grype (M2) | M1, M2 |
| Outdated container base images and OS packages | Trivy, Grype (needs container-image targets) | M3 |
| Software inventory (what versions you ship) | Syft (SBOM) | M2 |
| Old or forgotten endpoints, backup and leftover files, directory listings | ffuf on every URL target: SecLists `common.txt` (4,751 paths) on local targets, SiegeKit's own 210 paths on deployed ones (delivered in M2.5c, [ADR 0027](adr/0027-ffuf.md)); Nuclei; Nikto (optional) | M2 |
| Exposed admin pages and dashboards | Nuclei panel templates (delivered in M2.5b), ffuf (delivered in M2.5c), ZAP spider | M2 |
| Default vendor logins left enabled | `nuclei-default-login`: Nuclei's 337 HTTP default-login templates (pinned v10.5.2), each documented factory login sent once (PeopleSoft's on each of 20 paths), on local targets after confirmation; non-HTTP services (SSH, databases) and the WordPress password-list template are not run (delivered in M2.6b, [ADR 0031](adr/0031-default-logins.md)) | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| No limit on failed login attempts | `login-throttle`: up to 50 logins (20 by default) for your own test account with a random wrong password, one per second, on local targets, after one login with the account's right password that must be answered differently, or the check fails instead of reporting; logins that are page forms (Next.js Server Actions, CSRF-token forms) with `--login-page`; a limit seen in the status, `Retry-After`, the redirect, the words (also on the page a wrong login redirects to) or the time. Measured: Next.js 16 with Supabase Auth (both form patterns), Django 5.2, Rails 8.1, Laravel 12 with Breeze; forms built only by JavaScript are not tested; deployed targets from M2.10 (delivered in M2.6a, [ADR 0030](adr/0030-login-throttling.md); forms and the guard [ADR 0062](adr/0062-form-logins.md)) | M2 ([ADR 0010](adr/0010-login-checks.md)) |
| Session cookie flags, security headers, TLS settings | ZAP crawl and passive checks on every URL target (delivered in M2.4, [ADR 0023](adr/0023-active-web-scans.md)); Nuclei header and cookie templates on every URL target (delivered in M2.5b). TLS settings: not yet, Nuclei's SSL templates cannot pass the egress proxy | M2 |
| Injection (SQL, command, template), XSS, SSRF patterns | Bandit (Python) and gosec (Go) code, M1; Opengrep for other languages, M2; ZAP attack scan on the running app, local targets only (delivered in M2.4; deployed targets wait for M2.10); Nuclei, sqlmap, M2 | M1, M2 |
| XML external entities (XXE) | ZAP's rule 90023 in the attack scan, on the requests of the person's `--har` recording (every GET, HEAD, POST, PUT, PATCH and DELETE to the target, at most 100), local targets only, after the "test accounts" confirmation ([ADR 0047](adr/0047-recorded-requests-to-zap.md)). The same recorded requests also get ZAP's other attack rules (for example SQL injection in a JSON login). XML endpoints not recorded, XML bodies declared only in an OpenAPI spec (ZAP's import cannot send them, measured), XML in file uploads (unverified), out-of-band XXE and SAML are not tested | M2 |
| Known CVEs in deployed software | Nuclei CVE templates on every URL target; intrusive ones on local targets only (delivered in M2.5b) | M2 |
| API endpoints that crash or leak errors on bad input | Schemathesis on local URL targets with an OpenAPI or Swagger 2.0 spec, from `--openapi` or found at one of 11 common paths (delivered in M2.5d, [ADR 0028](adr/0028-schemathesis.md); the 11th, swagger-ui-express's setup script, in [ADR 0046](adr/0046-public-api-maps.md)). APIs without a spec are not tested by it | M2 |
| "Attack maps" anyone can download: an API spec or source maps that show an attacker the routes and code | `public-maps`: one GET to each of 11 common spec paths, including the spec inside a Swagger UI page at `/api-docs/`, and the source maps of the scripts and styles the start page links (named, or `<file>.map`); each one served is a low finding. On every URL target, deployed ones included. Specs at other paths, Swagger UI mounted elsewhere, GraphQL schemas and maps of scripts loaded later are not found ([ADR 0046](adr/0046-public-api-maps.md)) | M2 |
| Misconfigured Dockerfiles, Kubernetes, Terraform | Checkov (M1); Hadolint (optional, not scheduled). Trivy runs only its dependency scanner. | M1 |
| Crashes and memory bugs on malformed input | Go fuzzing, Atheris, cargo-fuzz, AFL++ (optional) | M3 |
| Weak password hashes in data you supply | hashcat (GPU), John the Ripper (CPU), offline only | M3 |
| One user reading or changing another user's data (IDOR/BOLA), admin functions open to normal users | `access-control`: the GET and HEAD requests of a browser recording made as test account A (`--har`, at most 100), plus OpenAPI GET routes without path parameters, and on local targets every GET route of the spec (JSON or YAML) filled with IDs the recording showed (at most 500; [ADR 0052](adr/0052-route-sweep.md): finds Rocket.Chat's `chat.getDeletedMessages` leak, which no client calls), and with `--source` the GET routes of the app's server code, spec or not (Go routers, Rocket.Chat's REST API, Express; [ADR 0053](adr/0053-routes-from-server-code.md)), replayed as account C (`SIEGEKIT_SESSION_C`, outside every space A shares) and account B (`SIEGEKIT_SESSION_B`); reported when C or B gets A's exact answer, with data, while no login is refused; high with an ID in the URL or A's login name in the answer, otherwise medium (check by hand); low (`b-only-read`, `b-only-write`) when only B gets it and C is refused, as a member of a shared space is by design ([ADR 0051](adr/0051-outsider-account-c.md)). On every URL target. Heuristic and partial: pages the recording, the spec and the server code did not reach (routes other frameworks register, paths built at run time, wildcards, mounted routers), IDs the recording did not show, slug-named parameters, changes (POST, PUT, PATCH, DELETE) and answers that differ on every request are not tested (delivered in M2.7a, [ADR 0035](adr/0035-access-control-replay.md)) | M2 ([ADR 0011](adr/0011-app-logic-and-ai-checks.md)) |
| One user changing or deleting another user's data, writes with no login | `access-control-write`, only with `--replay-writes` on local targets: the recording's POST, PUT, PATCH and DELETE requests (at most 50) replayed as account B and with no login on a fresh copy of A's object, with the sender's own CSRF token, plus PUT, PATCH and DELETE tried on objects A read or made (at most 50), and A's earlier writes sent again before a POST on an object they prepared; high when A's same-URL read changed after a PUT, PATCH or DELETE, otherwise medium (check by hand). Measured: Juice Shop 10 of 11 real write flaws confirmed by hand (6 high, 4 medium) with a recording of every change its UI offers; Gitea's web UI 4 medium, all allowed by design. GraphQL mutations are replayed and queries skipped; method calls sent as POST (Rocket.Chat's DDP `method.call`, JSON-RPC) are told apart by method name, their IDs read in the params and their refusals inside a 200 answer ([ADR 0050](adr/0050-method-calls-sent-as-post.md); Rocket.Chat 6.13.1: 16 false medium before, 1 medium allowed by design after; Kanboard v1.2.48's JSON-RPC: 2 false medium before, 0 after, every B write refused); SockJS and Socket.IO polling requests are not replayed. Not tested: writes the recording did not make other than those tries, slug-named objects (A's real object is used), multi-step flows whose steps do not name the object in a JSON body, and WebSocket messages; GraphQL access control is not measured on an app with accounts; POST-only apps never reach high ([ADR 0049](adr/0049-write-replay.md)) | M2 (ADR 0011) |
| API routes with no login required | `access-control`: each replayed request is also sent with no login; reported (medium: public pages name their authors by design) when it gets A's exact answer containing A's login name (`--har-user`), and high (`no-login-secret`) when a JSON answer has a field named like a password, hash, secret, key or token with a value, such as Juice Shop's password hashes or Memos's OAuth client secret (CVE-2025-65797). Data readable with no login that neither names A nor has such a field, such as other users' names and addresses, is not reported (delivered in M2.7a, [ADR 0035](adr/0035-access-control-replay.md)) | M2 (ADR 0011) |
| Supabase tables without row-level security, open Firebase rules | Static rules (M1); since [ADR 0064](adr/0064-static-supabase-rules.md) `backend-rules` replays `supabase/` migrations in order: tables without RLS or with RLS disabled later, policies that are always true (by role and command), views without `security_invoker`, materialized views in `public`, storage policies that never check the caller, grants and revokes deciding who can reach each table; Firebase rules whose condition never checks `request.auth` (size-only writes, test mode); weak Supabase Auth settings in `supabase/config.toml`; test folders and files never read. Checked against PostgreSQL 16 and Supabase's linter; not followed: SQL built at run time, extensions' objects, schemas exposed besides `public`; `backend-live`: one read-only GET per Supabase table or Realtime Database path with the app's own public key, names from the app's scripts and `--source` migrations and rules; the backend must appear in the scripts and a person types its host (M2.7c). Not tested live: Firestore, tables named nowhere, table writes | M1, M2 (ADR 0011, [0037](adr/0037-backend-live-check.md)) |
| Storage buckets anyone can upload to (Firebase Storage, Supabase Storage) | `storage-write`, only with `--storage-url` on local targets: one 36-byte text file uploaded with the app's public key (or no login), read back and deleted at the root of each bucket and in folders named in the app's scripts or, with `--source`, in `storage.rules` and `supabase/` migrations, at most 5 files; a person types the storage host (or the Firebase bucket) and `write test files`; each accepted upload is critical, and a file whose delete is refused is named. Measured: 6 of 6 open Firebase rule sets on the emulator and 6 of 6 open Supabase policy sets on a local stack, where the rules file found 4 and 0. Not tested: folders named nowhere, rules that allow only some file types or only the user's own folder, real hosted projects (unverified), what the app's storage triggers create ([ADR 0058](adr/0058-storage-write-test.md)) | M2 |
| Missing rate limits on expensive or AI endpoints | `rate-limit`: up to 50 requests (20 by default), one per second, to one URL you name with `--rate-limit-url` (GET, or POST with `--rate-limit-body`), on local targets; a limit counts as seen at a 429 or 503 answer or a `Retry-After`, `RateLimit-*` or `X-RateLimit-*` header; no limit is low. URLs behind a login, limits above the burst, per-IP limits and limits that only slow answers are not tested; deployed targets from M2.10 (delivered in M2.7b, [ADR 0036](adr/0036-rate-limit-check.md)) | M2 ([ADR 0011](adr/0011-app-logic-and-ai-checks.md)) |
| No limit on password-reset, sign-up or second-factor code pages | `reset-limit`, `signup-limit`, `code-limit`: 20 POSTs, one per second, to each page, given by flags or taken from the `--har` recording, with wrong answers and codes and new user names, on local targets; a code page allowing more than 100 wrong codes a day (limit per window from its headers; NIST SP 800-63B-4's 100 in a row) is low; a limit said only in words counts. With `--mail-catcher` (a local Mailpit), the emails each reset and sign-up sent are counted, and a reset that answers the same each time but sends fewer emails is limited ([ADR 0056](adr/0056-mail-catcher-count.md)); texts are not counted. Not seen: without a mail catcher, whether a reset that answers the same each time still limits its emails; limits above 20 requests or per IP address, pages behind a session the recording no longer holds (Gitea's code page answers 500 and the check fails). ([ADR 0055](adr/0055-rate-limit-pages.md)) | M2 |
| Password spraying past a per-account lockout | `login-spray`: after `login-throttle` saw a limit, 20 logins for invented user names with one wrong password; no limit is medium. Not measured on a real app with a per-account lockout, only on the test app ([ADR 0055](adr/0055-rate-limit-pages.md)) | M2 |
| CORS misconfiguration, open redirects, CSRF, file-upload flaws, path traversal, SSRF | Bandit and gosec where they have rules (M1); Opengrep (M2); ZAP attack scan on local targets (path traversal tested in M2.4); Nuclei on the running app (M2.5b: non-intrusive templates everywhere, intrusive ones such as PUT uploads on local targets only) | M1, M2 |
| AI provider keys (OpenAI, Anthropic and others) in code or bundles | Gitleaks | M1, M2 |
| AI model output reaching eval, shell, SQL or HTML unescaped | Static rules | M3 (ADR 0011) |
| Prompt injection and system-prompt leakage in the app's AI features | garak or promptfoo, optional | M3 (ADR 0011) |
| Mass assignment, excessive AI agency, logging gaps | Manual | n/a |
| Business-logic flaws (skipping steps, price tampering) | Manual | n/a |
| Cloud account settings (buckets, IAM, firewalls) | Manual (not in scope for 1.0) | n/a |
| Password guessing against live logins | Not provided, by design | n/a |

Declined on 2026-11-19 by the owner: flagging runtimes and frameworks that are past end-of-life without a known vulnerability. It is not a security issue in itself, and no data source with a confirmed license was found. Known vulnerabilities in old versions are still found by Trivy.
