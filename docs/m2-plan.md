# M2 plan: active web and API testing

Status: in progress (started 2026-11-19, after the M1 sign-off). This splits the [roadmap](roadmap.md) M2 scope into small pull requests. Each one keeps CI and the real-repository gate green and is merged when all checks pass. Security-critical parts come first, before any tool can send traffic.

| PR | Scope | Main design | Done when |
| --- | --- | --- | --- |
| M2.1 | URL targets and address rules: parse `scan URL`, resolve the host once, classify addresses (loopback, private, public, always blocked), local mode with typed confirmation for private addresses, append-only audit log. No traffic is sent yet. | ADR 0005 | Unit and negative tests for every address class, including IPv6, IPv4-mapped IPv6, decimal and octal IP spellings, and names that resolve to blocked addresses. |
| M2.2 | Deployed mode: a 128-bit token per host (kept between runs, checked at the start of every run), check at `/.well-known/siegekit-verify.txt` (no redirects) or DNS TXT `_siegekit-verify.<host>`, address pinning, typed host confirmation in a terminal (`--authorized-host` is not accepted in deployed mode), no bypass flag. | ADR 0005 | Negative tests: wrong host, subdomain, redirect, stale token, rebinding to a private address. |
| M2.2a | Support for AI coding assistants (owner request, 2026-11-19): `siegekit agents` prints a guide (`docs/agents.md`) with commands, flags, exit codes, the `report.json` fields and safety rules; `report.json` gets `schemaVersion`; findings carry the tool's `helpUri` (https only) in JSON, SARIF and HTML; refusals send the person to a terminal. The person still authorizes every target and download: deployed targets need the host name typed, and the guide tells assistants never to confirm for the person. | ADR 0005, 0016 | A test fails if a `report.json` field is missing from the guide; a real Trivy run shows `schemaVersion` and `helpUri`. |
| M2.3 | Egress proxy: `target-only` plugins run with no network except a relay container whose only way out is a SiegeKit proxy on the host (ADR 0019 replaced the internal network of ADR 0018) that allows the pinned addresses only, enforces the rate cap, sets the `SiegeKit/<version>` User-Agent where possible, and stops the run after repeated server errors. | ADR 0006, 0018, 0019 | Proxy tests that try metadata addresses, other hosts, DNS to other names and direct connections from the tool container. This PR completes the first half of the M2 gate. Done in two PRs: the proxy itself, then its sandbox wiring with container tests. Active tests run on Linux first; macOS stays refused until a CI job on GitHub's Intel macOS runners (Colima) passes and the owner agrees (decided 2026-11-19). |
| M2.4 | Vulnerable web fixture and the first active plugin. Owner decisions of 2026-11-19 (ADR 0023): the fixture is SiegeKit's own small vulnerable app, used in tests and CI only (no `siegekit demo`); ZAP crawls and runs passive checks on every target, and its attack scan runs only on local targets until M2.10. The relay image (ADR 0019) joins the dependency consent prompt here. Done in two PRs: M2.4a adds `zap` and `zap-active`, the `localOnly` and `run.config` manifest fields and the active run path; M2.4b scans OWASP Juice Shop v20.4.0 in the CI gate. | ADR 0003, 0005, 0023 | Every planted fixture issue found by the ZAP rule listed for it; findings imported through ZAP's SARIF report. The gate's Juice Shop scan runs both ZAP plugins and reports missing CSP (10038) and a permissive CORS header (10098). |
| M2.5 | Nuclei and ffuf (exposed files, misconfigurations), Schemathesis for OpenAPI targets. Owner decisions of 2026-11-19 ([design](https://claude.ai/artifact/84fk3Qjt2mZhbDdBu9fxAg)): SiegeKit downloads pinned files from the publisher's GitHub releases, with consent (ADR 0024); ffuf's static binary runs in the pinned Alpine image; `nuclei` (no intrusive templates, no out-of-band callbacks) on every target and `nuclei-intrusive` on local targets only; ffuf uses SecLists `common.txt` on local targets and SiegeKit's own list of about 200 paths on deployed targets; Schemathesis uses `--openapi FILE_OR_URL`, or else the first spec found at a fixed list of default paths on local targets. Deployed targets stay GET and HEAD only, with no `--allow-destructive` before M2.10 (ADR 0025). Done in five PRs: M2.5a pinned downloads; M2.5b Nuclei; M2.5c ffuf; M2.5d Schemathesis and `--openapi`; M2.5e `--only` by family and `--profile`. | ADR 0003, 0016, 0023, 0024, 0025 | Every planted fixture issue found by the tool listed for it; destructive plugins run only on local targets, after confirmation; each coverage loss of ADR 0025 listed under "Not tested" in reports when it applies. |
| M2.6 | Login checks: login throttling with a test account and a random wrong password; default credentials (local mode only); secrets in served content. Owner decisions of 2026-11-20 ([design](https://claude.ai/artifact/62fVx5n5HBpLwfWXEwQ2mB), "1a 2a 3a 4a 5a", split ok): the login is given with `--login-url`, `--login-user` and `--login-body`; login throttling runs on local targets only until M2.10, and no limit is a medium finding; `nuclei-default-login` runs the HTTP default-login templates on local targets after confirmation (337 of 338: PeopleSoft's fuzz-tagged template added back, WordPress password-list guessing left out, owner decision of 2026-11-20); SiegeKit fetches the start page and the same-origin files it links (one level, at most 200) for Gitleaks. Done in three PRs: M2.6a login throttling (ADR 0030); M2.6b default credentials (ADR 0031); M2.6c secrets in served content (ADR 0032: `served-secrets`, on every target; a script's or style's source map counts as part of it). Added by the owner on 2026-11-20: M2.6d, a static check for weak or default passwords written into a repository's files, with no login attempts ([design](https://claude.ai/artifact/2iDYSAqkwibQajztdWp678), answers "1b 2b 3a 4a 5a" after a measurement on 24 repositories): config files, credentials in URLs and code in any language; the SecLists 10,000 most common passwords plus vendor defaults, values shorter than 12 characters, and values equal to the user or key name; templates, tests (by folder and file name), translation files, documentation and code comments skipped and counted; medium, CWE-521 and CWE-798; its own PR, which measures the real check on the same repositories plus Java and C# apps before merging (ADR 0034: `weak-passwords`; 76 reported on 28 repositories, 74 true). | ADR 0010, 0030, 0031, 0032, 0034 | Tests show limits are enforced (count, rate, deployed-mode gating). |
| M2.7 | App-logic checks: authorization differential, unauthenticated route check, rate-limit check, live backend-rules check. | ADR 0011 | Fixture issues found. |
| M2.8 | Passive tools moved from M1: OSV-Scanner, Syft (SBOM), Grype. | ADR 0003, 0014 | Planted issues found; real-repository gate still green. |
| M2.9 | Opengrep, a pinned binary downloaded as in ADR 0024 (built in M2.5a), with SiegeKit's own Apache-2.0 rules for JavaScript and TypeScript; opengrep-rules only downloaded after license acceptance. First test whether Opengrep runs mobsfscan's LGPL rules for Android and iOS source, then decide between them and mobsfscan (ADR 0033 item 4). | ADR 0003, 0016 | Planted issues found on Linux and macOS, amd64 and arm64. |
| M2.10 | Optional sqlmap and Nikto; measure and set the default request rate; full M2 gate run. | ADR 0005 | M2 gate: all target-authorization negative tests pass and all known issues in the vulnerable web fixture are detected. The milestone check includes the hand triage of results ([milestones/README.md](milestones/README.md)). Then the owner signs off. |

Added at the owner's request on 2026-11-19, outside the numbered PRs: a check for environment files. The `gitleaks-history` plugin scans every commit for secrets and committed `.env` files, and the built-in `dotenv-gitignore` check warns when `.gitignore` does not exclude them. Manifests gain `run.env` and `requiresGit` for this.

Every PR that adds a command, flag or report field also updates `docs/agents.md`.

Every new dependency (tool image, binary, fixture image) goes through the ADR 0016 consent prompt and ADR 0008 pinning (digest, at least 7 days old).

Open questions are asked of the owner when a PR reaches them, not guessed.
