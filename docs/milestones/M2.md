## Known gaps
- Static Supabase rules (ADR 0064) read text, not a database: `execute format(...)`, objects made by extensions, `search_path` changes and schemas exposed besides `public` are not followed; a function called in a storage policy is assumed to check the caller. Not yet covered: public buckets that allow listing, `SECURITY DEFINER` functions callable by `anon`, `auth.users` behind a view, policies on `user_metadata` (splinter 0025, 0028, 0002, 0015); views are not in the `--source` table list for `backend-live`.
- The egress proxy answers a request it cannot parse with 400 and does not count it (Go's server does this before SiegeKit's handler). ADR 0065 removed the cause seen on Juice Shop; a tool that sends malformed requests another way would lose them without a trace. For the M2 milestone check.
- Secrets and dependencies (ADR 0063), for the M2 milestone check: the Supabase CLI's public local secret key is still a high `generic-api-key` finding on a line such as `SUPABASE_SECRET_KEY=…` (as before), and the older Supabase demo JWTs of local stacks are reported by Gitleaks' `jwt` rule (not measured); leaving them out under every rule needs a global `[[allowlists]]`, which makes Gitleaks refuse repository files that use `[allowlist]` (measured). A repository rule that matches the same secret as a SiegeKit rule reports it twice. The tree scan reads git-ignored files. Trivy leaves development dependencies of pnpm lockfiles before version 9 out. Trivy's development flag is measured for npm, Yarn, Bun and uv lockfiles only (the report says so). The history scan on a shallow clone sees only the commits it has and does not say so (CI's self-scan checks out depth 1): another cause than SK-1, not changed here.
- Backends the scripts do not name (ADR 0061): the tie for a hosted backend is the project gateway's key check; a Supabase served without its gateway accepts any key there, so only the typed host remains. A Firebase backend the scripts do not name is still refused. The kind from `--source` needs `supabase/` or Firebase's config files in the repository. Server Action logins (Porchlet finding 3) and the shared login limit (finding 5) are PRs B and C of the same plan.
- arm64 (ADR 0060): fuzzing runs on amd64 only. Apple-chip macOS with a container engine is not tested (needs a Mac the owner has). The gate's wall time rose to 24.2 min with the arm64 jobs (one run); `max-parallel: 10` on the repository scan, whose reason is not recorded, is left for the owner.
- XXE (ADR 0047) is tested only on endpoints the person's `--har` recording holds: XML endpoints not recorded, XML bodies declared only in an OpenAPI spec, out-of-band XXE (the target cannot reach ZAP's callback inside the sandbox) and SAML (no add-on in the pinned image) are not tested. Juice Shop's Docker image has its XXE switched off, so only the test app shows it.
- `public-maps` finds a spec only at 11 paths: other paths, Swagger UI mounted elsewhere than `/api-docs` or loading its spec from a URL, Redoc and GraphQL schemas are not found; on deployed targets the spec found is reported but not given to Schemathesis or access-control (ADR 0046).
