## Verified

- Nuclei (PR #35): with the pinned image and a local copy of the v10.5.2 templates (same files as the pinned archive, built from the git tag), `TestNucleiFindsPlantedIssues` finds every planted issue through the relay and proxy: `nuclei` sent 10,852 requests and reported missing headers, `/.git/config` and `/.env`; `nuclei-intrusive` sent 1,000 and reported the PUT upload. CI runs it with the real archive, downloaded and checked as in ADR 0024. Measured: about 10,500 to 10,900 requests per full run, peak memory about 900 MiB, `nuclei-intrusive` killed at 1 GiB.
- Lost requests found and fixed (PR #35): CI's first run missed the planted `.env` (rule `laravel-env`); a local run missed `codeigniter-env`, another `cookies-without-httponly`. Measured with temporary counters: the egress proxy held a slot for every open tool connection, idle ones included, so 779 connections waited, the longest 27 s, past Nuclei's 10 s timeout; after that fix the relay's cap of 64 was hit (Nuclei peaks at 299 open). Now the limit counts connections to the target and the relay allows 1,024 (ADR 0026 item 6). New `TestConnectionLimit` fails on the old proxy (a third client times out behind two idle ones) and passes now; at most 2 requests reach the target with `MaxConns` 2. With the fix every planted issue was found locally, and the Nuclei run took 150 s instead of about 250 s. Not yet known: whether ZAP lost requests the same way before the fix (its planted issues were always found).
- macOS test job (PR #35): the first macOS run since M2.4 (earlier ones were never started by GitHub) failed the URL scan tests, because they assumed a Linux host; the same tests fail on main with the host set to macOS. The tests now set the Linux host themselves; the macOS refusal stays covered by `TestScanURLNotRun`.
- ffuf (PR #36): `TestFFUFFindsPlantedIssues` runs the pinned binary in the pinned Alpine image through the relay and proxy with the local list: 4,758 requests (4,751 paths plus calibration), 0 refused, 53 s; it reported the planted `/.env` and `/.git/config`. `TestWordlist` checks that local and deployed runs get their own list mounted at `{wordlist}`; `TestPinned` checks the shipped SecLists file's SHA-256. The ffuf archives' SHA-256 values match the publisher's checksums file (downloaded 2026-11-20). The parser is tested on real ffuf 2.3.0 output, including auto-calibration against an app that answers every path. Not run locally: the deployed list against a real deployed target.
- Schemathesis (PR #37): `TestSchemathesisFindsPlantedIssues` runs the pinned image through the relay and proxy against the test app's API, with the spec fetched by `egress.Get`: 10 of 10 runs reported `ST101` (server error) on `/api/items/{id}`, 18 to 30 requests each. Real CLI runs, local: Juice Shop v20.4.0 has no spec at the 10 default paths (each answers HTML, a 301 or a 500), so `schemathesis` is skipped and the paths are listed; a small Python API was found at `/openapi.json` and gave 6 findings from 10 requests; `--openapi` with a YAML file whose server URL is `https://prod.example.com/api` sent its 102 requests to the target under `/api`. Measured and avoided: `--max-time` made Schemathesis resend a failing request 6,173 times in 40 s, which tripped the proxy's stop after 100 server errors (ADR 0028). `TestScanURLOpenAPI` covers the flag (file, URL, other origin refused before any request, missing file, not a spec, default paths, none found); `TestOpenAPISpec` the mount, exit codes 0, 1 and 2, and the base path in locations. Not tested: HTTPS targets (the CA is passed in `REQUESTS_CA_BUNDLE`, unverified for Schemathesis), and large APIs against the 15-minute timeout.
- Address rules (PR #14, re-check): loopback is allowed. A private address without a terminal is refused; it is allowed with `--authorized-host` or with the host typed. 169.254.169.254 and `0x7f000001` are refused. `FuzzParse` (target) runs in CI.
- Deployed-mode negative tests (PR #15): wrong token, a certificate for another host, redirect, 404, a token past the read limit or inside a line, a TXT record on a parent or sibling name, a subdomain using the parent's token, a stale token, a name resolving to a private address, a mismatched typed name. `--authorized-host` and runs without a terminal are refused before any request. ## Result quality

The full triage runs at the M2 milestone check (rules in [README.md](README.md)). Seen so far, not from a sample:

- False positives: SiegeKit's own repository had 4 secrets findings, all fake test keys (re-check F12, marked in #32). On the test fixture, ZAP's `zap-active` reports "Remote OS Command Injection" (rule 90020) on `/file?name=cat /etc/passwd`: the fixture answers any name containing `etc/passwd` with fake file contents, which fools that rule. The real flaw there is path traversal, which rule 6 also reports.
- Misses: on OWASP Juice Shop v20.4.0 the attack scan reported none of Juice Shop's known injection flaws, because ZAP's spider does not crawl single-page apps (see Known gaps). Deployed targets get no attack scan until M2.10.
- Seen while building M2.5b, to count in the M2 triage: Nuclei's `waf-detect` reports "apachegeneric" for the test app, which only sends an Apache `Server` header (a false positive as a WAF finding, informational severity).
- Seen while building M2.5c, to count in the M2 triage: on the test app ffuf reports `/render/https://www.google.com` (a SecLists entry) only because Go's server redirects the double slash, and the app's real pages `/search`, `/item` and `/file`, which are not flaws.
- Seen while building M2.5c, to count in the M2 triage: on Juice Shop v20.4.0 (CI gate) ffuf reported 20 paths from 4,758 requests.
- Seen while building M2.5d, to count in the M2 triage: on the test app Schemathesis also reports `ST103` (undocumented status code) for the planted 500, which is the same bug seen by a second check. In one batch of 5 runs against a crash on negative ids with no minimum in the spec, 1 run found nothing (random inputs; the test app now documents `minimum: 1`, which the coverage phase always crosses). Juice Shop is not tested by Schemathesis: no spec at the default paths.
- Not measured yet: the false-positive rate of any check on the 20-repository gate, the miss rate on real apps, and whether severities are right.

## Unverified

- Pinned downloads through a proxy that intercepts TLS. A real download of an ffuf release asset (through GitHub's redirect to `release-assets.githubusercontent.com`) was checked by hand in the development sandbox for #34, not in CI.
- Byte stability of GitHub-generated source archives: the Nuclei templates archive was downloaded twice on a GitHub Actions runner with identical bytes (ADR 0026). Whether GitHub keeps those bytes over time is not known; a change fails the checksum, never runs (ADR 0024).
- Deployed mode against a real public host over real DNS. The development sandbox cannot resolve public names.
- Rootless Docker and Podman for active runs and the relay. No rootless warning is added until they are tested (owner decision).
- macOS for active runs: refused by design until the Colima CI job passes.
- Schemathesis against HTTPS targets and against APIs large enough to reach its 15-minute timeout.
- ZAP against HTTPS targets, Podman, and ZAP's memory on large apps beyond Juice Shop.
- Deployed mode with ZAP end to end: the read-only rule and passive checks are tested in units, not against a real public site.
- Whether a given AI assistant's shell counts as a terminal. Either way the rules hold, because deployed targets need a terminal.

## Known gaps

- Pinned files are checked against their SHA-256 only; upstream signatures are not verified yet (ADR 0024).
- Old versions of pinned files stay on disk after a pin is upgraded; there is no remove command yet.
- ZAP's spider follows HTML links only, so single-page apps are mostly not crawled (Juice Shop: no injection findings). Ajax spider or OpenAPI import is not decided.
- The `zap` crawl can still follow links that change data with GET on a deployed target; staging is recommended.
