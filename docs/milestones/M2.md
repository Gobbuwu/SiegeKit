## Known gaps
- `public-maps` finds a spec only at 11 paths: other paths, Swagger UI mounted elsewhere than `/api-docs` or loading its spec from a URL, Redoc and GraphQL schemas are not found; on deployed targets the spec found is reported but not given to Schemathesis or access-control (ADR 0046).
- `weak-passwords` misses weak passwords of 12 or more characters that are not on the list (`mysecretpassword`, `IamUsedForTesting`), anything in skipped files and comments, and keys that do not name a password (ADR 0034).
- Fixed by #52. Found while merging M2.6c: "relay containers left behind" failed 3 times, not once as first recorded (F10): on #41, on `main` `fb41e76` (CI run 44599932003) and on `main` `5e1997f` (CI run 44875915763). Cause (F8): the check listed every `siegekit-relay-*` container on the engine while `internal/sandbox`'s tests, run at the same time by `go test ./...`, start relays with the same prefix. Reproduced locally: a relay-named container that the test did not start fails the old check and is ignored by the new one, and a real leftover still fails the new one. Not verified: that each of the 3 CI failures had this cause.

- `access-control` tests only what the recording reached and the recorded IDs; no changes (POST, PUT, PATCH, DELETE); answers that differ on every request never match; data readable with no login that neither names account A nor has a field named like a secret is not reported, nor are secrets given only to logged-in accounts that differ between A and B (ADR 0035).
- Pinned files are checked against their SHA-256 only; upstream signatures are not verified yet (ADR 0024).
- Old versions of pinned files stay on disk after a pin is upgraded; there is no remove command yet.
- ZAP's spider follows HTML links only, so single-page apps are mostly not crawled (Juice Shop: no injection findings). Ajax spider or OpenAPI import is not decided.
- The `zap` crawl can still follow links that change data with GET on a deployed target; staging is recommended.
- The request-rate default is provisional until M2.10.
- Login throttling is not tested on deployed targets until M2.10 (owner decision, ADR 0030).
- `rate-limit` tests one URL per run, only on local targets until M2.10, only URLs that answer without a login, and does not see limits above the burst, per IP address, that only slow answers, or that answer 200 with no header (ADR 0036). On a single-page app a mistyped URL is reported as not limited.
